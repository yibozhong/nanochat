假设与实验设计

研究对象为六系数 token-dependent Chord。初速度有三个候选：零初速、独立 token 速度表和从归一化 h0 生成。默认初速度待定。

本轮以已完成的 h0 生成版（2e37a95d）为参照，新增零初速、独立速度表两个完整 Chord 实验。假设是初速度的来源会改变早期及最终 CE。三者共用 vanilla 主干、六系数 token-dependent 更新、数据顺序、seed 42 和 1B 学习率日程。

判据是完整预算下的 validation CE 差值，并检查差距在训练中的变化。并列报告参数量、训练 FLOPs、同型号 GPU 上的吞吐及峰值显存。两种初速度的参数量和优化器分组均有差异，结论适用于这一整体替换。

procedural-pretraining

Procedural pretraining

检验在相同 NanoChat 主干、初始化、训练步数和理论训练 FLOPs 下，将开头一段 FineWeb-Edu 换成程序数据，能否用更少 FineWeb tokens 达到基线的验证 CE。对照组为同一架构、seed、注意力后端和上下文的纯 FineWeb 训练。

数据与监督

使用 Jiang 等人公开生成器的 9 个 token 任务。每个输入输出已经是现有 RustBPE 词表内的 ID；模型两端与语言训练共用同一套参数。论文 · 原始生成器和配置

任务 生成和训练目标
identity、reverse、sort 复制、反转或升序排列，只监督答案
set、union 单序列或两段序列按首次出现顺序去重，只监督答案
delete 输入给出去除的符号，按公开代码删除其第一次出现，只监督答案
stack 先偏向 push、后偏向 pop，栈内符号唯一，从栈顶到栈底输出，只监督答案
dyck、dyck_shuffle 64 对括号，嵌套或按未闭合类型采样。监督同一序列内每个有效下一 token

输入输出任务默认 64 个输入符号。修正后的生成器在所有训练和验证样本中固定使用原生 ID 1–99，与作者公开配置中的采样范围一致。模型的输入表和读出层均有 32,768 个原生位置。Union 等变换任务按作者算法训练器的 102 类计算 CE（0–99、分隔、填充），Dyck 使用 129 类。FineWeb 始终使用全部 32,768 类。Stack 使用 0 编码 POP，最后两个原生词表 ID 分别用于分隔与填充。第一篇附录 A 将 Union 写作 103 类，发布的生成器在两个分隔位置用同一个 token，训练器实际构造 102 类。本实验采用公开代码的定义。生成器 · 训练器Dyck 默认使用完整上下文，括号配对在整次训练中固定。第一篇的 Rule 110 实验使用专用二值输入和输出投影，公开的 token 生成器不含该任务。

为配对 packed2K 基线，多条独立生成的完整样本放入同一因果上下文，样本间留一个边界位置，尾部填充。新实验在每条样本开头重置 RoPE，用文档掩码隔离样本。程序训练使用 PyTorch 高效 SDPA 的完整因果三角，保持基线的矩阵几何；语言训练沿用 FA2。边界、填充和输入输出任务的提示均不贡献 loss。读出层对所有模型位置做完整 32,768 词表投影，然后取任务类别并做 softmax。梯度按整个优化器 batch 的有效 target 数归一化。

两阶段训练

两阶段都使用既有 NanoChat 优化器和 LR 配方。阶段切换时在同一模型上新建优化器，不复制或重置任何模型参数，语言日程从第 0 步按剩余步数运行，FineWeb 从训练缓存第 0 行开始。中断恢复保留所在阶段的模型、优化器、随机状态和数据位置。整模型迁移协议，附录 A.2

现有训练入口为 python -m scripts.connection_train，调度入口为 research/connections/native/chord/submit.py。在同一 baseline recipe 上添加以下参数即可启用实验组，省略这些参数即为纯 FineWeb 对照。本次 Union 实验与 vanilla 基线 a2793a7e 配对，seed 42，FA2，16 × 2048，保留基线的置零输出投影。

--procedural-task union --procedural-tokens 10000000 --procedural-input-length 64
